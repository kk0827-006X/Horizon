## [Microsoft Copilot Cowork Vulnerability Exfiltrates Files](https://simonwillison.net/2026/May/26/copilot-cowork-exfiltrates-files/#atom-everything) ⭐️ 9.0/10

A security vulnerability in Microsoft Copilot Cowork allows agents to send emails to the user's inbox without approval, and external images in those emails can trigger network requests that exfiltrate data when the user opens the message. This enables prompt injection attacks to leak pre-authenticated OneDrive download links, allowing attackers to download files. This vulnerability highlights the fundamental security challenges in agentic AI systems, where autonomous agents with tool access can be exploited to exfiltrate sensitive data. As major products like Microsoft Copilot integrate agentic features, such flaws pose significant risks to enterprise data security. The attack leverages external image rendering in emails to exfiltrate data via network requests. OneDrive's pre-authenticated download links compound the risk, enabling attackers to directly download files without credentials.

rss · Simon Willison · May 26, 15:36

**Background**: Prompt injection is a cybersecurity exploit where malicious inputs cause large language models to behave unintentionally. In agentic systems, AI agents can perform actions like sending emails and accessing cloud storage, making them susceptible to indirect prompt injection if they retrieve untrusted content. Pre-authenticated download links from OneDrive allow file access without additional authentication, which becomes a vector for data exfiltration when combined with prompt injection.

## [Go Approves Generic Methods for Future Release](https://github.com/golang/go/issues/77273) ⭐️ 8.0/10

The Go team has officially approved the proposal for generic methods, allowing methods to have their own type parameters. The proposal, authored by Go co-designer Robert Griesemer, now moves to implementation. This fills a major gap in Go's generics implementation, which previously only supported generic functions and types. It enables more expressive and reusable code, particularly for data access layers and functional programming patterns. Generic methods were initially excluded from Go 1.18's generics due to implementation complexity. The approved proposal reverses the FAQ stance that they were not needed, and implementation work has begun.

hackernews · f311a · May 27, 09:02 · [Discussion](https://news.ycombinator.com/item?id=48291575)

**Background**: Go introduced generics in version 1.18 (March 2022), but only for functions and types; methods could not have their own type parameters. This limitation was a common pain point for developers coming from languages like Java or C++. The Go team had previously stated in the FAQ that generic methods were not a priority, but community demand led to a re-evaluation.
