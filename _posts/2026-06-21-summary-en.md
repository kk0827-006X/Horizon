## [CSSQuake: Quake Rendered Entirely with CSS and HTML](https://cssquake.com/) ⭐️ 8.0/10

CSSQuake is a port of id Software's Quake that renders BSP worlds as real HTML/CSS 3D geometry through the PolyCSS engine, without using WebGL or canvas. It preprocesses original Quake data into browser-ready JSON and runs the game in TypeScript, requiring JavaScript to function. This project demonstrates the extreme capabilities of CSS 3D transforms and DOM-based rendering, pushing the boundaries of what can be achieved with web standards. It sparks discussion on browser performance, retro gaming, and creative coding, inspiring the developer community. CSSQuake uses PolyCSS to convert Quake BSP maps into styled DOM elements with 3D transforms and preserve-3d. It relies on JavaScript for game logic, input handling, and asset loading, so it is not pure CSS but a significant technical achievement.

hackernews · msalsas · Jun 20, 10:49 · [Discussion](https://news.ycombinator.com/item?id=48608223)

**Background**: CSS 3D transforms allow positioning elements in 3D space using transform-style: preserve-3d and perspective. Previously, projects like cssDOOM proved that classic games could be recreated with CSS, but CSSQuake extends this to a full 3D engine. The PolyCSS engine precomputes geometry into CSS.

This project bridges the gap between classic Unix/Linux desktop environments and Apple's mixed reality platform, enabling developers and enthusiasts to use legacy X11 applications in spatial computing. ## [DOS Game F-15 Strike Eagle II Reverse Engineering Project Seeks Testers](https://neuviemeporte.github.io/f15-se2/2026/06/20/needyou.html) ⭐️ 6.0/10

The reverse engineering project for the DOS game F-15 Strike Eagle II has released a playable DOS version and is seeking testers to help find bugs as it converts assembler code to binary-equal C code, with the ultimate goal of porting to Linux and Windows. This project is significant for software preservation and retro gaming, as it demonstrates a rigorous approach to porting classic games by first fully reversing to assembler than translating to C, ensuring accuracy while enabling modern platform support. The project's two-step process involves reversing the original game to assembler, then converting that assembler into binary-equal compiled C code while still running on DOS; only after all assembler code is replaced will porting to modern systems begin.

hackernews · LowLevelMahn · Jun 20, 15:10 · [Discussion](https://news.ycombinator.com/item?id=48609766)

**Background**: Reverse engineering old DOS games is challenging due to heavy use of 16-bit assembly and platform-specific tricks. Converting assembly to C involves reconstructing control structures and handling indirect addressing. Porting games from DOS to modern platforms requires understanding these low-level details and replacing them with portable code.
